# 語言與翻譯 {#language-and-translation}

文件站提供繁體中文、English 與简体中文。切換語言時會開啟同一篇文章的對應版本；所選文件語言會保留在網址中，因此重新整理或加入書籤後仍會維持該語言。

應用介面提供繁體中文、English 與簡體中文。選擇後會保存於同源瀏覽器儲存空間 `localStorage` 的 `ordivant.locale`，並同步到其他分頁。變更介面語言不會重載頁面或清除表單。首次使用且尚未選擇時，應用會參考 `navigator.languages`：繁體中文地區代碼 `zh-TW`、`zh-HK`、`zh-MO` 使用繁體中文；其他中文地區使用簡體中文；英文使用 English；不支援的語言使用繁體中文。

語言切換只會改變應用介面、文件站導覽、搜尋介面與文件文字。Ordivant 不會自動翻譯使用者建立的 Work 專案與任務、Agent 指示、訊息、Knowledge 文件、Code 內容或模型回覆。這些內容會依照提交者輸入的語言保存，使用者與 Agent 必須自行選擇合適的語言。

## 開發應用介面翻譯 {#developing-application-translations}

應用翻譯位於 `frontend/src/i18n`。語言代碼為 `zh-TW`、`zh-CN` 與 `en`；繁體中文文案是 source key，英文對照放在 `catalogs/*.en.ts`，簡體中文對照放在 `catalogs/*.zh-CN.json`。source key 和 `useI18n()` 的 `t()` 僅供介面文案使用，不要拿來翻譯使用者建立的內容。

元件使用 `useI18n()` 訂閱目前語言並取得 `t()`。需要將錯誤或狀態訊息保存到 React state 時，使用 `localized(source, values)` 保存原始文案與插值值；顯示時再交給 `t()`，語言變更後就能呈現新語言，且不會丟失訊息內容。表單呼叫 `useLocalizedForm(form)`；語言變更只會重新驗證已有錯誤的欄位，不會送出表單、清除草稿或重設欄位值。

```sh
npm --prefix frontend run i18n:generate
npm --prefix frontend run i18n:check
```

`i18n:generate` 離線使用固定的 OpenCC 詞彙轉換，從繁體中文 source key 產生簡體中文 JSON。`i18n:check` 驗證目錄對照、插值 placeholder 與程式碼中的翻譯 key；修改英文目錄或 source key 後也要重新產生並檢查簡體中文目錄。

應用介面瀏覽器驗收需要已啟動、owner 為 `ordivant-execution-qa` 且使用 8092 的 QA 環境，以及其中的合成帳號。wrapper 會在程序記憶體中提供測試帳號資料：

```sh
uv --cache-dir .cache/uv run --project backend --no-sync python scripts/execution_browser.py scripts/i18n_browser.cjs
```

文件站瀏覽器驗收預設使用本機 preview `http://127.0.0.1:4174/`，也可以明確指定正式 Pages 網址。先執行 `npm run preview --prefix docs`，再執行其中一種命令：

```sh
node scripts/i18n_docs_browser.cjs
node scripts/i18n_docs_browser.cjs --base https://ordivant-ai.github.io/
```

## 參與翻譯 {#contributing-translations}

繁體中文根目錄是目前的文件來源。其他語言使用相同的相對路徑，例如 `docs/guide/work.md` 對應 `docs/en/guide/work.md` 與 `docs/zh-CN/guide/work.md`。

- 以繁體中文原文為準，保持功能、限制、數字與安全說明一致。
- 不翻譯命令、API 路徑、環境變數、程式碼、JSON 範例、產品名稱與穩定的技術識別字。
- 保留同一篇文章的相對連結、標題 anchor、圖片路徑和程式碼區塊；新增或移動標題時同步檢查連結。
- 更新翻譯時，對照原文與另外兩種語言，避免只更新導覽或首頁而漏掉操作及契約細節。
- 執行文件建置與 `scripts/check_docs.py`，並在 PR 中列出來源頁面與已更新的語言。

翻譯尚未完成時，請明確指出缺少的語言版本，不要以另一種語言的原文充當翻譯。

## 檢查文件正文 {#checking-document-body}

建置前會檢查每一種語言的標題、段落、表格與首頁文案。中文頁面中的未翻譯英文正文，以及英文頁面中的中文正文會使檢查失敗；命令、程式碼、API 識別字與產品名稱不在翻譯範圍內。檢查包含原先容器指南整段漏翻的回歸案例。

```sh
npm --prefix docs run i18n:check
npm --prefix docs run build
uv --cache-dir .cache/uv run --project backend --no-sync python scripts/check_docs.py
```

瀏覽器驗收會實際開啟全部三語頁面並檢查可見正文，包括標題、段落及表格。它也會檢查語言切換、搜尋、手機導覽、容器章節書籤與本地化的 404 訊息。自動檢查用來找出漏翻，翻譯者仍需對照三語內容，確認功能、限制與用詞準確。

## 文件站發布 {#documentation-publishing}

原始碼位於 `ordivant-ai/ordivant`，正式文件站為 <https://ordivant-ai.github.io/>。網站由 `ordivant-ai/ordivant-ai.github.io` 的 GitHub Actions 讀取公開原始碼、建置並發布；應用服務需另行部署。

原組織專案路徑 `/ordivant/` 會轉至根站對應文章，並保留查詢參數與章節書籤。移轉前的使用者站網址已停止提供文件，請更新書籤為正式文件站。

原始碼倉庫保留專案 Pages 端點；Documentation 工作流程在三語正文與連結檢查通過後，只向此端點發布三語轉址頁。正式文件內容由根站倉庫發布。

文件站每 15 分鐘檢查來源 revision，沒有變更時跳過建置；GitHub 排程可能延遲。需要立即發布時，具有文件站倉庫權限的維護者可手動觸發：

```sh
gh workflow run pages.yml --repo ordivant-ai/ordivant-ai.github.io
```

原始碼倉庫的 Documentation 工作流程會執行相同的正文與連結檢查。網站建置成功後，`source-revision.txt` 會記錄實際發布的來源 commit，方便確認網站與原始碼是否同步。

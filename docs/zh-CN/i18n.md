# 语言与翻译 {#language-and-translation}

文件站提供繁体中文、English 与简体中文。切换语言时会开启同一篇文章的对应版本；所选文件语言会保留在网址中，因此重新整理或加入书签后仍会维持该语言。

应用界面提供繁体中文、English 与简体中文。选择后会保存于同源浏览器存储空间 `localStorage` 的 `ordivant.locale`，并同步到其他标签页。变更界面语言不会重载页面或清除表单。首次使用且尚未选择时，应用会参考 `navigator.languages`：繁体中文地区代码 `zh-TW`、`zh-HK`、`zh-MO` 使用繁体中文；其他中文地区使用简体中文；英文使用 English；不支持的语言使用繁体中文。

语言切换只会改变应用界面、文档站导航、搜索界面与文档文字。Ordivant 不会自动翻译用户建立的 Work 项目与任务、Agent 指示、消息、Knowledge 文档、Code 内容或模型回复。这些内容会依照提交者输入的语言保存，用户与 Agent 必须自行选择合适的语言。

## 开发应用界面翻译 {#developing-application-translations}

应用翻译位于 `frontend/src/i18n`。语言代码为 `zh-TW`、`zh-CN` 和 `en`；繁体中文文案是 source key，英文对照存放在 `catalogs/*.en.ts`，简体中文对照存放在 `catalogs/*.zh-CN.json`。source key 和 `useI18n()` 的 `t()` 仅用于界面文案，不要用来翻译用户创建的内容。

组件使用 `useI18n()` 订阅当前语言并获取 `t()`。需要将错误或状态消息保存在 React state 时，使用 `localized(source, values)` 保存原始文案和插值值；显示时再交给 `t()`，语言变更后就能显示为新语言，同时保留消息内容。表单调用 `useLocalizedForm(form)`；语言变更只会重新验证已有错误的字段，不会提交表单、清除草稿或重置字段值。

```sh
npm --prefix frontend run i18n:generate
npm --prefix frontend run i18n:check
```

`i18n:generate` 离线使用固定的 OpenCC 词汇转换，从繁体中文 source key 生成简体中文 JSON。`i18n:check` 验证目录对照、插值 placeholder 和代码中的翻译 key；修改英文目录或 source key 后也要重新生成并检查简体中文目录。

应用界面浏览器验收需要已启动、owner 为 `ordivant-execution-qa` 且使用 8092 的 QA 环境，以及其中的合成账号。wrapper 会在进程内存中提供测试账号数据：

```sh
uv --cache-dir .cache/uv run --project backend --no-sync python scripts/execution_browser.py scripts/i18n_browser.cjs
```

文件站浏览器验收默认使用本机 preview `http://127.0.0.1:4174/`，也可以明确指定正式 Pages 网址。先执行 `npm run preview --prefix docs`，再执行其中一种命令：

```sh
node scripts/i18n_docs_browser.cjs
node scripts/i18n_docs_browser.cjs --base https://ordivant-ai.github.io/
```

## 参与翻译 {#contributing-translations}

繁体中文根目录是目前的文件来源。其他语言使用相同的相对路径，例如 `docs/guide/work.md` 对应 `docs/en/guide/work.md` 与 `docs/zh-CN/guide/work.md`。

- 以繁体中文原文为准，保持功能、限制、数字与安全说明一致。
- 不翻译命令、API 路径、环境变量、代码、JSON 范例、产品名称与稳定的技术识别字。
- 保留同一篇文章的相对连结、标题 anchor、图片路径和代码区块；新增或移动标题时同步检查连结。
- 更新翻译时，对照原文与另外两种语言，避免只更新导览或首页而漏掉操作及契约细节。
- 执行文件建置与 `scripts/check_docs.py`，并在 PR 中列出来源页面与已更新的语言。

翻译尚未完成时，请明确指出缺少的语言版本，不要以另一种语言的原文充当翻译。

## 检查文档正文 {#checking-document-body}

构建前会检查每一种语言的标题、段落、表格与首页文案。中文页面中的未翻译英文正文，以及英文页面中的中文正文会导致检查失败；命令、代码、API 标识符与产品名称不属于翻译范围。检查包含原先容器指南整段漏译的回归案例。

```sh
npm --prefix docs run i18n:check
npm --prefix docs run build
uv --cache-dir .cache/uv run --project backend --no-sync python scripts/check_docs.py
```

浏览器验收会实际打开全部三语页面并检查可见正文，包括标题、段落及表格。它也会检查语言切换、搜索、手机导航、容器章节书签与本地化的 404 消息。自动检查用于发现漏译，翻译者仍需对照三语内容，确认功能、限制与用词准确。

## 文档站发布 {#documentation-publishing}

源代码位于 `ordivant-ai/ordivant`，正式文档站为 <https://ordivant-ai.github.io/>。网站由 `ordivant-ai/ordivant-ai.github.io` 的 GitHub Actions 读取公开源代码、构建并发布；应用服务需要单独部署。

原组织项目路径 `/ordivant/` 会跳转至根站对应文章，并保留查询参数与章节书签。迁移前的用户站网址已停止提供文档，请更新书签为正式文档站。

文档站每 15 分钟检查来源 revision，没有变更时跳过构建；GitHub 调度可能延迟。需要立即发布时，有文档站仓库权限的维护者可以手动触发：

```sh
gh workflow run pages.yml --repo ordivant-ai/ordivant-ai.github.io
```

源代码仓库的 Documentation 工作流程会执行相同的正文与链接检查。网站构建成功后，`source-revision.txt` 会记录实际发布的来源 commit，方便确认网站与源代码是否同步。

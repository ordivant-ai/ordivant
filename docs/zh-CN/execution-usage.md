# 运行、模板、自动流程与工具环境 {#runs-templates-workflows-and-tool-environments}

Work 的 Run 可执行任务、流程、已连接的工具或沙箱。先在 Work 选择项目和任务，指派 Agent 后即可查看进度、结果和待审成果。模型设置请参阅[模型连接指南](model-usage.md)；自托管环境的服务与功能启用方式请参阅[容器部署指南](containers.md)。

## 部署与功能启用 {#start}

使用已部署的 Work 时，请先确认管理员已启用所需的执行服务。沙箱是可选功能；任务也可以不使用沙箱。自托管时，请按照[容器部署指南](containers.md)选择并启用服务。

## Run 运行控制台 {#run-console}

1. 选择有权限的项目，在任务详情选择 Pi 执行 Agent，按「派发给 Agent」创建 Run。人工「认领任务」不会启动自动运行。
2. 打开「Run 运行」查看状态、进度、工具结果和已提交的成果。
3. 有权限的管理员可以要求暂停、继续、停止或重跑；另一位有权限的成员可以独立审查提交结果。

暂停会在当前模型或工具操作结束后生效，不会强行中断该操作。停止会结束 Run，并让未完成的任务回到可重新派发的状态；如果外部服务已经完成操作，停止不会撤销该操作。Run 结束后仍可查看已提交的成果。重跑会创建新的 Run；已经通过审查的任务不会因此重新打开。

Run 显示完成或已提交，不代表任务已验收。任务必须由有权限的独立审查者接受后才算完成。DEMO 用于展示流程，不会调用付费模型；使用真实模型时，Run 记录会显示供应商实际回报的模型和用量。没有提供的用量或美元费用会标记为未知，不能当作账单。

## Agent 模板 {#agent-templates}

在「自动化 → Agent 模板」设置角色、指令、模型、可用工具、沙箱和执行限制。修改模板会生成新版本。创建或编辑 Agent 时选择要使用的版本；模型或工具选项的变更只影响之后派发的任务。

模板不会授予项目或工具权限。Agent 必须已经获准访问该项目；模型连接由组织管理员设置。

## 自动工作流程 {#automated-workflows}

在「自动化 → 工作流程」添加步骤，指定 Agent 或所需能力，并设置步骤之间的依赖关系与独立审查者。没有依赖关系的步骤可以同时执行。

手动启动时输入本次流程的需求。系统会为每个步骤创建对应任务；如果没有合适的 Agent，或前置成果尚未通过审查，该步骤会等待。前置任务通过审查后，后续步骤才会继续。所有步骤都通过审查后，整个工作流程才算完成。

排程可以设置启动间隔和最多启动次数。同一排程已有流程运行时不会再次启动；服务停机期间错过的时段不会补跑。取消流程会停止尚未完成的步骤，已验收成果会保留。更新工作流程不会改变已经启动的流程。

<span id="外部-mcp-工具"></span>

## 外部 MCP 工具 {#external-mcp-tools}

添加连接前，部署管理员必须先允许受信任的 MCP 服务主机；默认不允许任何外部主机。自托管环境的允许列表设置方式见[容器部署指南](containers.md)。Work 管理员接着可以在「工具与沙箱」添加项目连接，填写 MCP HTTPS 网址和 bearer token，并选择 Agent 可以使用的工具名称。使用「测试连接」确认工具列表正确后，再把连接指派给 Agent。

请使用供应商提供的 HTTPS 网址，并把 token 填入专用字段，不要将账号信息或 token 放入网址。token 会加密保存，之后不会再次显示；留空可保留现有 token。平台不会通过重定向把认证转发到其他主机。私人或本机 HTTP 服务必须由部署管理员明确加入 `ORDIVANT_TOOL_HTTP_HOSTS`；如果目标解析到内网或 loopback 地址，也必须加入 `ORDIVANT_TOOL_PRIVATE_HOSTS`。私人 HTTPS 服务仍须使用有效的 TLS 证书。`ORDIVANT_TOOL_ALLOWED_HOSTS` 用于指定允许的 MCP 主机。

目前连接使用 bearer token；暂不支持交互式 MCP OAuth。外部工具可能会修改其他服务中的数据：结果不明确时，平台不会自动重做操作。派工前请确认所选工具及其影响范围。

<span id="沙箱"></span>

## 沙箱 {#sandboxes}

管理员可以为项目设置沙箱限制，例如命令时间、内存、CPU、进程数、输出量和工作区大小，再应用到 Agent。每次 Run 都有独立的临时工作区，并按照设置限制可执行的命令。

沙箱没有网络，也无法访问主机目录，不能在线下载软件包或任意克隆 Git 仓库。只能使用沙箱环境中已有的工具与依赖。命令失败或超时时，结果会显示相应状态。

工作区会在 Run 结束、停止或超时后清理。需要保留的文件和测试输出，请在 Run 结束前提交为成果或证据；工作区不是长期文件存储空间。如果页面无法确认已清理，请联系部署管理员检查执行环境。Docker 沙箱与主机共用 kernel；如果组织要求 VM 级别隔离，部署管理员需要使用 VM 或 microVM 执行环境。

<span id="隔離驗收"></span>

## 在项目中验证运行结果 {#isolated-acceptance}

先派发一项低风险任务，确认 Run 能启动、提交成果并由另一位有权限的成员独立审查。DEMO 只验证产品流程，不表示调用过付费模型；使用已设置的模型时，请先确认模型供应商及其费用政策。

使用外部工具前，先测试连接并确认可用工具列表。首次验证应选择只读操作，或只创建可以安全清理的测试数据；到上游服务确认实际结果。停止 Run 不会撤销外部服务已完成的操作，结果不明确的操作也不会自动重做。

使用沙箱时，请先把要交付的文件和测试结果提交为成果，再结束 Run。结束后确认页面显示工作区已清理；如果清理状态未确认，请交由部署管理员检查。

# 執行、範本、自動流程與工具環境 {#runs-templates-workflows-and-tool-environments}

Work 的 Run 可執行任務、流程、已連接的工具或沙箱。先在 Work 選擇專案與任務，指派 Agent 後即可查看進度、結果及待審成果。模型設定請參閱[模型連線指南](model-usage.md)；自架環境的服務與功能啟用方式請參閱[容器部署指南](containers.md)。

## 部署與功能啟用 {#start}

使用已部署的 Work 時，請先確認管理員已啟用所需的執行服務。沙箱為選用功能；任務也可以不使用沙箱。若要自架，請依[容器部署指南](containers.md)選擇並啟用服務。

## Run 執行控制台 {#run-console}

1. 選擇有權限的專案，在任務詳細資料選擇 Pi 執行 Agent，按「派發給 Agent」建立 Run。人工「認領任務」不會啟動自動執行。
2. 開啟「Run 執行」查看狀態、進度、工具結果與已提交的成果。
3. 有權限的管理者可要求暫停、繼續、停止或重跑；另一位具備權限的成員可以獨立審查提交結果。

暫停會在目前正在進行的模型或工具操作結束後生效，不會強行中斷該操作。停止會結束 Run，並讓未完成的任務回到可重新派發的狀態；若外部服務已完成操作，停止不會撤銷該操作。Run 結束後仍可查看已提交的成果。重跑會建立新的 Run；已完成審查的任務不會因此重新開啟。

Run 顯示完成或已提交，不代表任務已驗收。任務必須由符合權限的獨立審查者接受，才算完成。DEMO 用來展示流程，不會呼叫付費模型；使用真實模型時，Run 記錄會顯示供應商實際回報的模型與用量。未提供的用量或美元費用會標示為未知，不能當作帳單。

## Agent 範本 {#agent-templates}

在「自動化 → Agent 範本」建立角色、指令、模型、可用工具、沙箱與執行限制。修改後會產生新版本。建立或編輯 Agent 時選擇要使用的版本；另行設定的模型或工具選項只會影響之後新派發的任務。

範本不會授予專案或工具權限。Agent 必須已獲准存取該專案；模型連線由組織管理員設定。

## 自動工作流程 {#automated-workflows}

在「自動化 → 工作流程」新增步驟、指定 Agent 或所需能力，並設定步驟之間的依賴關係與獨立審查者。互不相依的步驟可以同時執行。

手動啟動時輸入本次流程的需求。每個步驟會建立對應任務；若沒有合適的 Agent，或前置成果尚未通過審查，該步驟會等待。前置任務通過審查後，後續步驟才會繼續。所有步驟完成審查後，整個工作流程才算完成。

排程可設定啟動間隔及最多執行次數。同一排程已有流程執行時不會重複啟動；服務停機期間錯過的時段不會補跑。取消流程會停止尚未完成的步驟，已驗收的成果會保留。更新流程不會改變已啟動的流程。

## 外部 MCP 工具 {#external-mcp-tools}

新增連線前，部署管理員必須先允許信任的 MCP 服務主機；預設不允許任何外部主機。自架環境的允許清單設定方式見[容器部署指南](containers.md)。Work 管理員接著可在「工具與沙箱」新增專案連線，填入 MCP HTTPS 網址、Bearer token，並選擇 Agent 可使用的工具名稱。使用「測試連線」確認清單正確後，再把連線指派給 Agent。

請使用供應商提供的 HTTPS 網址，並將 token 填在專用欄位，不要把帳密或 token 放進網址。token 會加密保存，之後不會再次顯示；留白可保留目前 token。平台不會透過重新導向把認證轉送到其他主機。私人或本機 HTTP 服務必須由部署管理員明確加入 `ORDIVANT_TOOL_HTTP_HOSTS`；若目標解析到內網或 loopback 位址，也必須加入 `ORDIVANT_TOOL_PRIVATE_HOSTS`。私人 HTTPS 服務仍須使用有效的 TLS 憑證。允許的 MCP 主機由 `ORDIVANT_TOOL_ALLOWED_HOSTS` 控制。

目前連線使用 Bearer token；尚未提供互動式 MCP OAuth。外部工具可能會修改其他服務中的資料：結果不明時平台不會自動重做操作。派工前請確認所選工具與其影響範圍。

## 沙箱 {#sandboxes}

管理員可為專案設定沙箱限制，例如命令時間、記憶體、CPU、程序數、輸出量與工作區大小，再套用到 Agent。每次 Run 都有獨立的暫存工作區，並依設定限制可執行的命令。

沙箱不連接網路，無法存取主機目錄，也不能線上下載套件或任意複製 Git repository。只能使用沙箱環境中已有的工具與依賴。命令逾時或失敗時，結果會顯示相應狀態。

工作區會在 Run 結束、停止或逾時後清除。需要保留的檔案與測試輸出，請在 Run 結束前提交為成果或證據；工作區不是長期檔案儲存空間。若畫面顯示清理尚未確認，請聯絡部署管理員檢查執行環境。Docker 沙箱與主機共用 kernel；若組織要求 VM 等級隔離，部署管理員需改用 VM 或 microVM 執行環境。

## 在專案中驗證執行結果 {#isolated-acceptance}

先派發一項低風險任務，確認 Run 能開始、提交成果並由另一位有權限的成員獨立審查。DEMO 只驗證產品流程，不表示曾呼叫付費模型；使用已設定的模型時，請先確認模型供應商及其費用政策。

使用外部工具前，先測試連線並確認可用工具清單。初次驗證應選擇只讀操作，或只建立可安全清理的測試資料；到上游服務確認實際結果。停止 Run 不會撤銷外部服務已完成的操作，結果不明的操作也不會自動重做。

使用沙箱時，請先把要交付的檔案與測試結果提交為成果，再結束 Run。完成後確認畫面顯示工作區已清理；若清理狀態未確認，請交由部署管理員檢查。
